# 关键决策依据

## ADR-01 · 不上 pydantic-graph

你的拓扑里唯一的"图性"是：
- 一个条件分支（分诊拒诊）
- 一次并行扇出（横向核验）
- 一条线性链（主 Agent 内部）

这三件事用 `if/else` + `asyncio.gather` 表达，代码更短、调试更直接。

**升级触发条件**：
1. 流程需要挂起数小时等医生审方后再跨进程恢复
2. 需要时间旅行调试
3. 分支数 >= 5

## ADR-02 · 纵向内聚为 1 个主 Agent

辨证→立法→选方→加减是**强依赖链**，拆 agent 会：
- 丢原始四诊细节（选方要看兼症）
- 误差逐级累积
- 成本 ×4

**正解**：1 个 Agent 一次调用输出嵌套 `Diagnosis`。

## ADR-03 · 不用 DeepSeek Harness

| 维度 | PydanticAI | DeepSeek Harness |
|---|---|---|
| 定位 | Python agent **开发框架** | TypeScript agent **运行时平台** |
| 结构化输出 | **核心特性** | 非核心 |
| 验证回路 | 声明式 | 需手写事件监听 |
| 语言 | Python | TypeScript/Node |

你的项目是"构建特定领域 agent **功能**"，不是"构建 agent **平台**"。**选 PydanticAI**。

## ADR-04 · 反思机制 = 外部验证器驱动重试

ACL 2025 主会论文实测：无条件"让模型再想想"让准确率下降 2%-21%。

**正解**：`@output_validator` 里跑可判真假的硬验证，失败 `raise ModelRetry(具体证据)`。

## ADR-05 · 分诊 = 确定性代码，LLM 只有上调权

红旗规则的触发必须是关键词/规则匹配。LLM 分诊只能**追加**风险等级，永远不能把规则判定的红旗降级为绿。

命中即终止，不交给模型"解释一下"。

## v1.1 三处修正

### 修正 1：missing_info 分级（不是一刀切）

原方案："缺脉象 + 缺舌象 → 直接不出方"
问题：脉象在远程场景默认就是缺失的，会拒掉绝大多数正常请求。

修正：
- 缺脉象：0 惩罚
- 缺舌象：-0.5
- 缺舌象 + 核心症状 < 3：拒答

### 修正 2：V1 图谱路径分级（不是时间开关）

原方案："Phase 3 前降级、之后升级"
修正：按本次证候是否在图谱覆盖内**动态判定**。

### 修正 3：阈值标定加负样本

原方案：只做正样本 P25
修正：必须加 20 个负样本验证误纳率 <= 10%。

## 弃选方案记录

### 弃选 1：拆 4 个 agent

理由：丢上下文、误差累积、成本 ×4。

### 弃选 2：自我反思

理由：实测掉分（ACL 2025）。

### 弃选 3：DeepSeek Harness

理由：抽象层级不对、需要 TypeScript、重复造轮子。

### 弃选 4：Neo4j 向量索引

理由：HNSW 延迟高 9 倍、过滤语法不稳定、无原生混合检索。让 Neo4j 干图谱的活，向量交给 pgvector。

### 弃选 5：LLM 直接出克数

理由：LLM 对数值把控差（麻黄可能 3g→15g）。改为三段式：LLM 出意图 → 代码用表算 → clamp 到药典区间。
